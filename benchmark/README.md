# Benchmark КТ2

Набор в `queries.jsonl` зафиксирован до прогона: **30 документов D01–D30, 10 обычных вопросов и 5 ловушек** по занятию 3, с. 37–42. Обычные вопросы охватывают ASSYST PLUS, моторное масло, давление шин и проверки жидкостей для трёх моделей. Для каждого есть минимум три релевантных ID и эталон. Ловушки спрашивают о цене ТО, моменте затяжки, допуске АКПП, периоде замены тормозной жидкости и времени работы сервиса: этих сведений нет в выбранном корпусе.

Документ — отдельная индексируемая карточка из раздела руководства; 30 карточек получены из трёх PDF. Корпус намеренно небольшой, содержит короткие пересказы; качество на нём нельзя переносить на все руководства и вопросы владельцев.

## Запуск

Из корня репозитория с установленными зависимостями и работающей Ollama:

```bash
python -m benchmark.run --output benchmark/reports/repeat.json
```

Скрипт вызывает тот же `RAGService`, что и `/api/ask`. На вход генератору поступают только вопрос, модель автомобиля и выдача BM25. Поля `relevant` и `reference_answer` в prompt не передаются. Прогон сохраняет по каждому вопросу ранжированные ID, score, страницы, ответ API или ошибку и время. Отдельно фиксируются SHA-256 корпуса, вопросов и исходников Python в `backend/`, `search/`, `benchmark/`, базовый commit, модель и её digest, параметры BM25, температура и seed. Пока все вопросы не обработаны, `complete` равен `false`.

Без Ollama можно проверить только поиск:

```bash
python -m benchmark.run --retrieval-only --output tmp/retrieval.json
```

Такой прогон не даёт Accuracy и Correct Rejection Rate. `questions.example.jsonl` сохранён с КТ1 как пример старого формата; в проверке не участвует.

## Четыре метрики

| Метрика | Как считается |
| --- | --- |
| Recall@5 | Среднее по 10 обычным вопросам: доля эталонных документов в первых пяти |
| MRR@5 | Среднее по тем же 10 вопросам: 1 / ранг первого релевантного документа; если в top-5 его нет — 0 |
| Accuracy | Доля полностью правильных ответов из 10: все части эталона, сохранённые условия, без неподтверждённых утверждений |
| Correct Rejection Rate | Доля ответов `no_context` из 5 ловушек; HTTP-ошибка/ошибка генерации не считается отказом |

В этом прогоне k = 5, глубина MRR = 5. Согласование глубины с преподавателем не подтверждено; при изменении следует пересчитать выдачу и метрики с теми же вопросами.

Оценка ответов хранится отдельно: `report_sha256`, затем `answers` с полями `id`, `correct` (boolean), `reason`. Оценка 1 выставляется только полностью правильному ответу. Файл относится к одному конкретному прогону; проверка хеша не позволяет применить старые оценки к новым ответам.

```bash
python -m benchmark.score benchmark/reports/kt2.json benchmark/reports/kt2-reviews.json
```

Выдача и эталоны открыты для повторной проверки командой; независимое review участников не заявлено как выполненное. Четыре значения также сохранены в [kt2-metrics.json](reports/kt2-metrics.json). Итоговые значения и разбор каждого сбоя — [reports/kt2-summary.md](reports/kt2-summary.md).

## Сравнение моделей

Для базового сравнения используются `qwen2.5:3b` и `qwen2.5:7b`, тот же корпус, вопросы и k. Запуск другой модели:

```bash
OLLAMA_MODEL=qwen2.5:3b python -m benchmark.run --output benchmark/reports/other-model.json
```

Это учебный набор разработки; он не является независимым holdout. Для КТ3 предусмотрены отдельные вопросы и эксперименты из [testing.md](../spec/tech/testing.md). Эталоны и оценки нельзя подавать генератору или менять после прогона ради улучшения метрик.

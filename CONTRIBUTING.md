# Совместная работа

Порядок SDD: спецификация → код → проверки → Pull Request → review → merge в `main`.

## Ветки

`main` — постоянная ветка с собранным приложением. Для задач используются `docs/`, `feat/`, `fix/`, `chore/`; постоянные ветки по участникам и `develop` не используются.

Ветки КТ2: `docs/kt2-tasks` — требования и документация; `feat/rag-core` — поиск, API, LLM, корпус и benchmark.

## Изменения

- Поведение и API фиксируются в `spec/` до изменения кода.
- Сообщения коммитов: `тип: содержание`, типы `feat`, `fix`, `docs`, `test`, `chore`.
- Проверки: `python3 scripts/check_docs.py`, `python -m pytest -q`, синтаксис `frontend/script.js`.
- Результаты benchmark сохраняются вместе с параметрами, выдачей и ответами.
- История `main` не переписывается; force-push не используется.
- Не публикуются секреты, персональные данные и исходные PDF руководств.
- Ответ модели выводится как текст; демо явно обозначается.

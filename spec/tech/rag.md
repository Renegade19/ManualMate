# RAG и BM25

## Корпус

30 документов D01–D30 — короткие адаптированные разделы руководств W205, W213 и X253. У каждого есть текст, название раздела, модель, исходное руководство и номер печатной страницы. Источники и SHA-256 PDF сохраняются в `corpus/manifest.json`. Исходные PDF не публикуются.

## Предобработка

`search/preprocess.py`: общий токенизатор корпуса и запроса, нижний регистр, лемматизация pymorphy3 и стоп-слова. Отрицания сохраняются. Регулярные выражения сохраняют технические обозначения `5W-30`, `MB 229.5`, `OM654`, `DOT 4+`. Лемматизация объединяет формы русских слов, не изменяя исходный текст, который показывается пользователю.

Синонимы добавляются только в запрос: например, «антифриз» → «охлаждающая жидкость». Подсветка использует исходные формы найденных слов.

## Поиск

Инвертированный индекс реализован самостоятельно: терм → {doc_id: TF}. Длины документов, N и средняя длина хранятся вместе с индексом. DF — длина списка документов терма. Готовые индексы не используются.

```text
IDF(t) = ln(1 + (N - DF(t) + 0.5) / (DF(t) + 0.5))
score(q,d) = Σ IDF(t) * TF(t,d)*(k1+1) / (TF(t,d)+k1*(1-b+b*len(d)/avgdl))
```

k1 = 1.2, b = 0.75, top-k = 5. Повторы слов запроса не удваивают вклад. При равных score порядок определяется doc_id. Ранжируются документы выбранной модели или общие документы; статистики вычисляются по всему корпусу. Индекс сохраняется в JSON с хешем корпуса и версией токенизатора.

## Ответ

При пустой выдаче или score ниже 0.5 возвращается `no_context`, LLM не вызывается. Вопрос о масле без уточнения узла возвращает `clarify`.

Ollama `qwen2.5:7b` получает вопрос, автомобиль и найденные документы. Prompt требует ответ только по контексту, сохранение условий и отказ, если данных недостаточно. Результат имеет JSON-схему; backend проверяет ссылки и числовые значения. Источники берутся из metadata, а не из текста модели. Ошибка генерации возвращает 503.

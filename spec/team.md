### Почему граница проходит именно так

- **BM25 у Backend.** Индекс и ранжирование — это движок, который работает внутри сервиса и должен быть быстрым и покрыт unit-тестами. Это инженерная задача, близкая к API.
- **Предобработка текста у LLM.** Токенизация, лемматизация и синонимы определяют качество поиска и ответа, а качество измеряет тот же участник через benchmark. Так один человек отвечает за весь путь «текст документа → фрагмент → prompt → ответ → метрика».
- **Контракт между Backend и LLM** — две функции: `preprocess(text) -> list[str]` (её пишет LLM, вызывает Backend при индексации и поиске) и `generate_answer(question, chunks) -> Answer` (её пишет LLM, вызывает Backend в `/api/ask`). Сигнатуры фиксируются в [architecture.md](tech/architecture.md#контракт-между-модулями).

## Общая ответственность

- Каждый умеет запустить проект по README и объяснить путь запроса: интерфейс → backend → BM25 → LLM → ответ с источником.
- Тестовые запросы для benchmark предлагают все трое, разметку релевантных документов проверяет второй человек.
- Pull Request проверяет не автор.

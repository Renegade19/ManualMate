# Frontend

Статические HTML, CSS и JavaScript без сборки. Дизайн и сценарии КТ1 сохранены; основной режим работает через HTTP API.

## Запуск

Из корня репозитория, после установки Python-зависимостей:

```bash
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000>. FastAPI раздаёт интерфейс и API с одного адреса; дополнительный сервер frontend не нужен.

Для отдельного сервера:

```bash
python3 -m http.server 8080 --directory frontend
```

В `config.js` задайте `apiBaseUrl: "http://127.0.0.1:8000"`, откройте <http://localhost:8080>. Backend разрешает эти локальные origin через CORS. Для другого адреса укажите `FRONTEND_ORIGINS` при запуске backend. Секреты и токены в конфигурацию frontend не добавляются. Тайм-аут `timeoutMs` по умолчанию — 120000 мс.

## Файлы

| Файл | Назначение |
| --- | --- |
| `index.html`, `styles.css` | Разметка и оформление справочника |
| `config.js` | Адрес API и тайм-аут |
| `api.js` | Fetch, отмена, ошибки HTTP, проверка формата JSON |
| `script.js` | Состояния экрана, модели, вопросы, источники, подсветка |
| `demo.js` | Отдельные демонстрационные ответы КТ1, только для `?demo=1` |

Список автомобилей загружается через `GET /api/vehicles`. Вопрос отправляется в `POST /api/ask`; `engine` отсутствует, если двигатель не выбран. В корпусе КТ2 сведения общие для модели, поэтому API не предлагает коды двигателей. При смене автомобиля или двигателя старый запрос отменяется. Ответы, фрагменты и названия выводятся через `textContent`.

Подсвечиваются буквальные совпадения `matched_terms`, полученных от backend. Backend возвращает исходные формы найденных слов: например, «маслом», а не только лемму «масло». Технические обозначения `5W-30`, `MB 229.5`, `DOT 4+` не разбиваются при подсветке.

## Демо КТ1

Откройте <http://127.0.0.1:8000/?demo=1> или <http://localhost:8080/?demo=1>. В этом режиме API и LLM не вызываются, видна метка «Демо-версия»; `?demo=1&error=1` показывает ошибку. Обычный режим при недоступности API показывает ошибку и кнопку повтора, не включает демо.

## Проверка

Python-зависимости берутся из корневого `requirements.txt`. Для браузерных проверок нужны Node.js 20+ и Playwright:

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm exec playwright install chromium
PYTHON=python corepack pnpm test:frontend
```

Если Chrome уже установлен, можно использовать `PLAYWRIGHT_CHANNEL=chrome`. Для полноценной проверки с Ollama добавьте `--live` к `node scripts/check_frontend.cjs`; обычная проверка использует явно обозначенные тестовые HTTP-ответы. Порт проверки — 18765, меняется через `TEST_PORT`.

Проверяются каталог, три статуса, источники, сноски, подсветка, небезопасный HTML как текст, HTTP 400/404/500/503, неверный JSON, тайм-аут, обрыв соединения, отмена при смене модели, повтор, localStorage, ввод и ширина 390 px. Сценарии — [scenarios.md](../spec/product/scenarios.md), фактические результаты — [checkpoint-2.md](../docs/checkpoint-2.md).
